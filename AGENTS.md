# Instructions for AI coding assistants (Claude Code, Cursor, Codex, Copilot...)

Azbuka: a local-first Russian A1 voice tutor (16-unit course, spoken audio, adaptive review) with optional account sync, for self-taught adults learning on their phone.

This repo is built task by task from a written plan. Follow this loop exactly; it exists to stop the project
drifting away from the plan.

## Where the plan lives
- `.taskmaster/docs/prd.md`: goal, non-goals, success criteria, stack, decision log. Read Goal and Non-goals every session.
- `.taskmaster/tasks/tasks.json`: phases, tasks, subtasks, status, dependencies, test strategy, work log. Source of truth.
- `.taskmaster/docs/parking-lot.md`: ideas that are NOT in the plan.
- `.taskmaster/docs/manual-checks.md`: checks waiting for a human or an agent with a running app.
- `TASKS.md`: generated from tasks.json. Never edit by hand.

Helper (Python stdlib only), from the repo root:
```
python .taskmaster/tasks.py status | phase [n] | next [--phase n] | show <id>
python .taskmaster/tasks.py set-status <id> in-progress|done|deferred|cancelled
python .taskmaster/tasks.py log <id> "plan: ..."     # timestamped note on a task
python .taskmaster/tasks.py add --help               # add a task or subtask
python .taskmaster/tasks.py validate                 # after any manual edit of tasks.json
python .taskmaster/render_tasks_md.py                # refresh TASKS.md
```

## Work loop (one task at a time)
1. `tasks.py next`, then `tasks.py show <id>`. Complexity 7+ without subtasks: split it into 3-5 subtasks first.
2. Read the code the task touches. Log your plan: `tasks.py log <id> "plan: files X, Y; approach ..."`.
3. `tasks.py set-status <id> in-progress`, build it, log what worked and what failed.
4. Run the task's testStrategy for real. Not done until it passes.
5. Drift check, `set-status <id> done`, `render_tasks_md.py`, commit with the id: `task 7.2: <title>`.

## Drift rules
- Only work on the task `next` returned. New ideas → dated line in `parking-lot.md`.
- Changing what's being built → PRD decision log first, then tasks, then code.
- Never reword a `done` task; add a corrective subtask. Cancel tasks, never delete them.

## Project
- Stack: Static single-file web app `standalone.html` generated by `scripts/build_standalone.py` from `curriculum/russian/`; FastAPI + asyncpg + argon2 in `backend/app/main.py`; PostgreSQL with numbered SQL migrations in `db/`; jsdom tests in `tests/`, pytest in `backend/tests/`
- Install: `python -m venv backend/venv && backend/venv/Scripts/python.exe -m pip install -q -r backend/requirements-dev.txt && (cd tests && npm ci --no-audit --no-fund)   # Linux: backend/venv/bin/python`
- Test: `(cd tests && npm test --silent) && python tests/check_build_in_sync.py && python scripts/validate_course_content.py && (cd backend && ALLOW_WIPE_TEST_DB=1 TEST_DATABASE_URL=$AZBUKA_TEST_DB venv/Scripts/python.exe -m pytest -q)   # AZBUKA_TEST_DB: see memory.md; on Linux scripts/test_backend.sh -q`
- Lint: `node --check service-worker.js && python -m py_compile backend/app/main.py scripts/build_standalone.py`
- Build: `python scripts/build_standalone.py && python scripts/generate_course_seed.py`
- Dev servers: defined in `.claude/dev-servers.json`; run with `python .claude/scripts/devserver.py start all`.

## Facts that are easy to get wrong
- `standalone.html` is generated: never edit it. Edit `scripts/build_standalone.py` or `curriculum/russian/a1-course.json`, rebuild, commit both; `tests/check_build_in_sync.py` fails on a stale build.
- When app assets change, bump `CACHE` in `service-worker.js` (currently `azbuka-standalone-vN`).
- Local save key is `localStorage["azbuka-standalone"]`; old saved data must keep loading. The app must work offline and signed out.
- Unit IDs `u07-shopping-clothing` and `u08-daily-routine` don't match their titles; IDs are stable keys, never rename.
- XP rules live on the server (`xp_ledger`, per-prefix caps, daily cap); client XP is only a display. Event ids: letters, digits and `._:@-`.
- `db/repeatable/course_units.sql` is generated by `scripts/generate_course_seed.py`; regenerate after course changes.
- The API refuses to start without `TOKEN_PEPPER` and `APP_ORIGINS`. Backend tests wipe their database: only a disposable one.
- Deploy = Docker Compose in `/opt/azbuka` on `root@2.25.108.3` (other apps live there: touch only `/opt/azbuka`, the `azbuka_*` Docker resources, its Traefik route for `azbuka.andel-vps.space`; port 8090 belongs to another site, use 8091). Inspect before changing. Not the VPS kit (`ssh vps`, `git push vps`).
- Repo docs number phases differently: `docs/MASTER_PLAN.md` Phases 2-7 = harness phases 1-5. tasks.json is the plan of record.
